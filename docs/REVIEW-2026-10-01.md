# Office Attendance review and refactor

Date: 1 October 2026 · Local version: 1.12.0

## Confirmed attendance rules

For each calendar month, using the configured standard day length:

- Work days = Office days + Home days.
- Days target = at least 50% of work days, rounded up to a whole office day.
- Hours target = at least 50% × work days × standard day length.
- Actual office hours are the sum of the recorded Office In/Out durations.
- Both requirements must pass independently. Year totals do not cancel out a
  shortfall in an individual month.

For 20 work days at 8 hours per day, the targets are 10 office days and 80 office
hours. Ten 6-hour office visits meet the days target but miss the hours target
by 20 hours.

The user's final correction supersedes the earlier Office-only hours denominator.
The final implementation uses Office + Home for actuals and projections. Existing
leave, Working sick, public holiday, non-working day and weekend exclusions remain.
Only coded Office/Home days enter the requirement; blank work days must be filled
in for a complete monthly result.

## Scope and approach

Reviewed the shared calculations, calendar and validation, HTTP/SQLite persistence,
browser persistence, frontend state and logging flows, summaries, import/export,
standalone build/service worker, versioning and deployment configuration.

Kept the existing dependency-free architecture and shared service used by both
editions. Changes target correctness, data preservation and clearer reporting.
There is no database migration or backup format change.

## Findings addressed

| Priority | Finding | Change |
| --- | --- | --- |
| High | Unreadable browser data was silently treated as a new empty history and could be overwritten. | Preserve the stored bytes, stop loading, and offer a raw recovery download. |
| High | Missing/malformed day records could act as deletes; a malformed replacement backup could erase data. | Validate object shapes and require an explicit code or explicit null clear operation before writing. |
| High | Restore could write days before failing on settings; calendar updates could be partial. | Wrap complete mutations in transactions, with nested SQLite savepoints and browser rollback. |
| High | Separate tabs could overwrite newer browser data from stale in-memory copies. | Reload before changes; coordinate service writes and metadata with a shared Web Lock where supported. |
| High | Rapid edits could read the previous code while a save was pending, losing the new selection. | Snapshot and overlay pending edits immediately; serialize mutations and roll back refused edits. |
| Medium | Old year responses could repaint the page after newer navigation had begun. | Accept only the latest requested state; refresh after navigation settles. |
| Medium | Successful saves followed by a refresh failure were reported as failed saves. | Report that the save succeeded and totals could not refresh. |
| Medium | Custom notes on calendar days could disappear when settings changed or old calendars were tidied. | Include comments in year bookkeeping and preserve annotated records during automatic calendar changes. |
| Medium | Equal In/Out times could be treated as missing and receive an estimated full day. | Determine completeness from valid times; a complete equal-time pair records zero hours. |
| Medium | A future FY could show future plans as month-to-date actuals; averages mixed planned and completed times. | Empty future month-to-date actuals and calculate displayed averages from completed days only. |
| Medium | Punch times used the browser zone while dates used the server zone; repeated taps and midnight could affect the wrong entry. | Use the app zone, check the date at punch time, guard repeated taps and selection changes, and explicitly handle the In shortcut. |
| Medium | Offline updates could mix files from different releases and delete unrelated origin caches. | Cache a complete release, wait for older tabs to close, and remove only caches belonging to this app's scope. |
| Medium | An arbitrary build output path could be recursively deleted. | Protect project/source paths and require an empty or builder-marked destination. |
| Medium | Standalone manifest URLs assumed site-root hosting. | Use relative scope, start URL, icon and shortcut paths. |
| Medium | NSW/ACT weekend ANZAC exceptions were extrapolated indefinitely. | Use recurring rules plus declared-year exceptions. |
| Low | Version tests used URL pathnames that became invalid Windows paths. | Use fileURLToPath. |
| Low | The hours denominator was difficult to see, and fractional day targets obscured the number of visits needed. | Show the hours formula and a whole-day target; label future plans. |

Time validation now has one shared implementation. Startup actions and the timer
also tolerate a page that has not loaded or has reached the recovery screen.

## Evidence and verification limits

- Initial test run: 97 tests, 93 passed; four version tests failed on Windows paths.
- An intermediate regression run after the main refactor: 124 tests passed.
- **The full suite has not been rerun after the final rule correction and subsequent
  calendar, holiday and browser metadata changes.** The intermediate result is not
  a claim that the final revision has passed every test.
- Built the standalone v1.12.0 output successfully into `dist/`.
- Viewed the updated desktop dashboard using a disposable SQLite preview with
  its date fixed to 14 October 2026. It showed 5/8 office days (62.5%) and 38/43
  required office hours, a 5-hour shortfall, with the correct visible denominator.
- Docker deployment, physical iPhone installation, mobile interaction flows and
  real browser offline-upgrade behaviour were not exercised in this review.
- User runtime attendance data was not used for writes. Changes remain local and
  uncommitted; no push, deployment or publication was performed.

Existing/new regression files cover workbook totals, zero-hour entries, future
periods, mutation ordering, stale navigation, malformed backups, transaction
rollback, storage failure, build destination guards and service-worker caching.
The final revision can be checked with `npm test` (or `node scripts/test.mjs`).

## Remaining operating constraints

- The self-hosted edition relies on a trusted network or authenticating reverse
  proxy. It has no built-in users/login. Existing published Docker ports bypass
  proxy authentication, as documented in README.
- Browser data remains device/origin specific. Web Locks protect writers that use
  this release in supporting browsers; older browsers have a reload-before-write
  fallback, not a guarantee against simultaneous tab writes. Keep JSON backups.
- A raw recovery download preserves corrupt data for repair; it is not necessarily
  importable. Automatic repair and a dedicated recovery restore workflow are not
  implemented.
- Old records do not identify whether PH/NW was assigned manually. Notes matching
  an exact generated holiday name are treated as automatic calendar text. A
  custom note or recorded time preserves the record during automatic changes.
- Calendar fixes do not rewrite historical attendance. Previously generated
  future calendars can be refreshed through Settings > Fill calendar.
- Holidays can change by government announcement. AFL dates beyond the confirmed
  table remain flagged rather than guessed; regional and historical one-off
  holidays may need manual entries.
- While an Office day is in progress, the to-date hours card postpones its
  denominator until both times exist. Full-month plans already include it.
  Missing past times are zero actual hours and display a warning.
- An Out time earlier than In remains an overnight duration, with a visible
  warning. There are no automatic break deductions or partial-day attendance
  weights; recorded times should represent the hours the user intends to count.
- Offline updates become active after all old app tabs/windows close. A first
  offline visit cannot work until a complete build has been cached.
